# 隨身碟模式

把板子的 SD 卡直接掛給電腦，不用拔卡。**插上 USB1 自動變隨身碟，拔線自動
回相簿並重新掃卡**，兩個方向都不用碰板子。

這不是獨立的應用程式，而是相簿的一個模式：外部 Flash 裡並存兩個 app，
由相簿開機時決定要跑哪一個。

| 位址 | 內容 |
|---|---|
| `0x70000000` | 相簿（bootloader 永遠跳這裡） |
| `0x71000000` | 隨身碟（ST 的 `MSC_Standalone`，經 `tools/patch_project.py` 改過） |

相簿在 `watchdog_feed()` 裡量 CN18 的 VBUS，偵測到就在 AXI SRAM 頂端
`0x24071BF0` 留下暗號 `"USBD"` 並重置；相簿的 `main()` **第一行**看到暗號就
跳過去。暗號一次有效（跳之前就清掉），所以隨身碟 app 之後不管是拔線重置還是
當掉重置，下一次開機一定回到相簿，**不會卡在隨身碟模式**。

## 硬體

- **接 USB1（CN18）**，底部兩顆 USB-C 靠右那顆。USB2（CN17）是全速的，
  只有 12 Mbps，慢二十倍。
- **這塊板子沒有 JP2。** ST 的 MSC readme 寫「for USB_HS: JP2」是錯的
  （從別塊板子抄來的）。UM3289 列出的跳線只有 JP1／JP3／JP5／JP6。
- **JP1 留在 STLK**：板子吃 CN7 進來的 5V。那個孔插充電器就行、不必是電腦，
  但**一定要一直插著** —— JP1 不能改到 USB1，否則拔線就斷電，相簿也不會跑。
- ST-LINK 與 USB1 可以同時接，那是正常的開發接法。

## 建置與燒錄

```bash
cd projects/usbdrive && ./scripts/build.sh && ./scripts/flash.sh
```

`flash.sh` 只寫 `0x71000000`，不會動到相簿。但 **bootloader 必須是有補開 HSE
的版本**（相簿的 `patch_project.py` 會植入）—— 少了它 USB 完全不會列舉。
換句話說，這個功能要成立，相簿那邊也得是新的：

```bash
cd projects/album && ./scripts/build.sh && ./scripts/flash.sh --boot
```

## 速度

讀 4.6 MB/s、寫 3.7 MB/s（ST 原始碼是 1.7 / 0.8）。

**還是比讀卡機（約 20 MB/s）慢五倍**，但瓶頸不是 USB —— 高速 USB 跑得到
40 MB/s，我們只用到十分之一。真正的瓶頸是 SD 與 USB 嚴格串列、沒有重疊，
要再快得做雙緩衝。搬幾百 MB 的影片還是拔卡用讀卡機快。

量速度**一定要先清作業系統快取**（重置板子讓磁碟區重新掛載），
不然會量到 1500 MB/s 的假數字（board-notes 20.15 同一個坑）。

## 兩個讓它成立的根因

都不在這個目錄的程式碼裡，但少任何一個都不會動。

**1. HSE。** `MSC_Standalone` **沒有自己的 `SystemClock_Config`**，時脈完全
繼承 bootloader。它原廠的 bootloader 走 HSE，而相簿的只開 HSI —— 但 USB HS
的 PHY 需要 `RCC_USBPHYCCLKSOURCE_HSE`。症狀極度誤導：**app 跑得好好的、
中斷正常、SD 也讀得到，就是電腦看不到裝置**。

修法是在相簿 bootloader 的 `SystemClock_Config` 補開 HSE，PLL 來源仍是 HSI，
所以相簿的時序完全不變。附帶發現：兩顆 bootloader 的 PLL **輸出頻率其實一樣**
（600 / 400 MHz），只是參考來源不同，所以只補 HSE 就夠。

**2. 快取一致性。** `usbd_storage_if.c` 的 SD 讀寫完全沒有快取維護，而
`BSP_SD_*Blocks_DMA` 是 DMA 進可快取的緩衝。症狀同樣誤導：**磁碟正確列舉、
容量對、連 MBR 分割表都讀得出來**（第一次讀時快取是冷的），**但檔案系統
掛不上** —— 之後每次讀 CPU 都拿到殘留的快取內容。

讀後 `SCB_InvalidateDCache()`、寫前 `SCB_CleanDCache()` 就好了。

## 拔線會自動回相簿（做法與三次失敗）

拔掉 USB1 之後板子會自己重置回相簿並重新掃卡，不用按 reset。

**事件用 `HAL_PCD_SuspendCallback`，條件用「主機真的讀過資料」。** 兩者都是
量出來的，不是猜的 —— 在同一次開機裡記錄所有 PCD 回呼的觸發次數與時間：

```
Disconnect  0 次                              <- 拔線根本不觸發，這條路是死的
Reset       1 次                              <- 列舉時的匯流排重置
Suspend     2 次：
    第 1 次  開機後   182 ms，host_active=0    <- 列舉期
    第 2 次  開機後 70812 ms，host_active=1    <- 拔線
```

同一支回呼會收到兩種完全不同的事件，**只能靠 `host_active` 分辨**。
只用時間門檻（「開機十秒後才算數」）是脆的。

三次失敗的嘗試，別再走：

- **主迴圈輪詢 VBUS**：拔線後 PD 堆疊把主迴圈卡住。實測迴圈計數完全不動，
  但 `uwTick` 照跳 —— 中斷活著、主迴圈死了。
- **SysTick 中斷裡讀 ADC**：斷線後 ADC 不再轉換，讀到的值沒有意義。
- **`Suspend` 無條件重置**：列舉期那次也會觸發，變成「相簿 → 隨身碟 →
  重置 → 相簿」的迴圈，電腦上連磁碟機代號都出不來。

還有一個獨立的坑，症狀是「有時候回得來、有時候回不來」：相簿清除暗號的寫入
如果還留在快取裡，會被隨身碟 app 的 `SCB_InvalidateDCache()` **直接丟掉**
（整體失效不會寫回髒資料），SRAM 裡留的還是舊暗號，下次開機又跳過去。
所以清暗號之後一定要 `SCB_CleanDCache_by_Addr()`。

## 使用注意

- **不要在複製到一半時拔線** —— 會得到不完整的檔案（任何隨身碟都一樣）。
- **不用按「安全地移除硬體」**。Windows 對這個裝置的移除策略是
  `ExpectSurpriseRemoval`（寫入快取關閉），複製完直接拔即可。
- 回到相簿會重新掃描卡片（實測 4300 多個檔案約 1.6 秒）——
  **這是必要的**，不重掃就看不到剛丟進去的新照片。
